# Security audit revenue operations

The paid, authorization-gated repository security review lives at
`/security-audit`. Its production flow is:

1. the customer selects one of the server-mapped plans;
2. the intake records the GitHub repository and authorization basis;
3. the server redirects to the Polar Checkout Link with the matching product;
4. Polar acts as merchant of record and processes the payment and taxes;
5. Polar signs an `order.paid` webhook after payment is fully processed;
6. work begins only after the repository scope and authorization are verified.

The customer cannot supply a product ID, price, success URL, webhook secret or
fulfillment destination. These remain controlled by the application and Polar.

## Required production configuration

The application needs one production secret:

```text
POLAR_WEBHOOK_SECRET=<generated by the dedicated Polar endpoint>
```

The dedicated endpoint is:

```text
https://unstash-open.vercel.app/api/security-audit/webhook
```

It must use raw payload format and subscribe only to:

- `order.paid`
- `order.refunded`
- `subscription.past_due`
- `subscription.revoked`

The route validates the Standard Webhooks signature against the raw request
body before processing the event. Never expose `POLAR_WEBHOOK_SECRET` through a
`NEXT_PUBLIC_` variable.

## Fulfillment notification

Polar is the payment and order system of record. A verified event can also be
forwarded to a private operations queue by setting:

```text
SECURITY_AUDIT_FULFILLMENT_WEBHOOK_URL=https://your-private-endpoint.example/audit-orders
SECURITY_AUDIT_FULFILLMENT_WEBHOOK_SECRET=<long random bearer token>
```

The notification contains the Polar event and order identifiers, selected
plan, customer email, repository, bounded scope notes, authorization flag,
payment status, amount and currency. It never contains card data or Polar
secrets. The Standard Webhooks event ID is sent as `Idempotency-Key`; the
receiver must safely ignore duplicate event IDs.

Without a private fulfillment URL, checkout continues to work and paid orders
remain visible in Polar. Operations must monitor the Polar order dashboard and
connect an alerting queue before buying paid traffic.

## Verification

Before promoting a new release:

1. submit each plan through `/security-audit/intake` without completing a real
   purchase;
2. confirm Polar shows the correct product, price, customer email, repository
   and scope fields;
3. confirm malformed repositories, missing authorization and missing terms are
   rejected before checkout;
4. confirm an invalid webhook signature receives HTTP 403;
5. use a Polar test delivery or sandbox order when testing fulfillment;
6. confirm webhook retries cannot create duplicate work.

The production Checkout Link should never be completed with a real card merely
as a deployment smoke test.

## Order handling playbook

For every paid order:

1. Match the fulfillment payload to the Polar order.
2. Re-check repository ownership or the live bug bounty policy.
3. Record the exact repository origin and immutable commit.
4. Send the scope contract for confirmation.
5. Request the least-privilege repository access needed.
6. Start the delivery clock only after authorization and access are complete.
7. Run the Authorized Bug Bounty Auditor workflow.
8. Deliver the redacted report and review call.
9. Remove private repository access after the engagement unless managed
   monitoring is active.

If authorization cannot be verified, stop before scanning and refund the
payment according to `/security-audit/terms`.

## First-revenue checklist

- Monitor the Polar order dashboard every business day until a private
  fulfillment queue is connected.
- Publish one sanitized sample report without client or secret data.
- Sell three beta audits before adding more scanner features.
- Track qualified visits, completed intakes, paid checkouts, delivery hours,
  confirmed findings, retest completion and managed-plan conversions.
- Never advertise a guaranteed vulnerability count or bounty payout.

GitHub Marketplace remains a later distribution channel. Direct Polar checkout
is the initial commercial path.
